# 工单 26 设计文档 — Skill 资产表结构与模型基座

> 日期：2026-08-25 ｜ 工单：`.scratch/ai-mvp/issues/26-Skill资产表结构与模型基座.md` ｜ 决策依据：ADR-0005（skill 统一资产双来源与发布固化）、ADR-0006（纯技能会话）
> 状态：已确认（用户批准方案 A 与分节设计；`published` 列类型按用户要求为 int）

## 1. 目标与范围

把 skill 资产演进到新存储形态，作为工单 27/28/29/32 的地基：

1. 资源文件从版本内容 JSON 拆出独立资源表（挂版本级，随版本不可变）；
2. skill 记录带上 Git 来源标记（`git_source_id` 软关联）与上架状态位（`published`）；
3. `name` 放宽 varchar(255)；
4. `SkillOwnerLevel` 移除 `PLATFORM` 枚举值（值域收敛 TENANT/USER）；
5. 新增上架/下架接口与管理页开关（纵切可演示）；
6. 既有全部功能（创建/版本/分页/物化/挂载/调试）在新结构上回归通过；
7. 数据库初始化脚本同步（DROP 重建，存量联调数据清空——既有约定）。

**不在本票范围**：`ai_skill_git_source` 表与同步逻辑（工单 29）、版本切换与预览接口（工单 27）、agent_file 固化（工单 28）、终端目录过滤消费（工单 32）。

## 2. 方案决策

**方案 A（采纳）：领域模型零重构，只动持久化形态。** `SkillContent` 值对象（markdown + resources Map）原样保留——长度/数量/路径防逃逸/base64 不变量不动；物化网关与挂载解析消费领域模型，运行链路零改动。变更收敛在基础设施层与 DDL。

被拒方案：

- **方案 B（资源升格为聚合内实体，带独立 id 可单独增删）**——违背「版本不可变」定案（资源可变即版本可变），引入无收益复杂度。
- **方案 C（不拆表，content 列改 jsonb）**——违背已定案的资源独立成表决策。

## 3. 分节设计

### 3.1 DDL（三表 + 新序列）

```sql
-- ai_skill：DROP 重建
name varchar(64) → varchar(255)                     -- 放宽
+ published int4 NOT NULL DEFAULT 0                 -- 上架位：0=下架 1=上架（int 而非 boolean，芋道惯例；用户定案）
+ git_source_id int8 NULL                           -- git 导入标记，软关联无 FK（ai_skill_git_source 表归工单 29 建）
-- 唯一索引维持：uk_ai_skill_name (owner_level, tenant_id, COALESCE(owner_user_id,0), name) WHERE deleted=0

-- ai_skill_version：DROP 重建
content → skill_markdown text NOT NULL               -- 列改名，语义=纯 SKILL.md（YAML frontmatter + 正文）

-- ai_skill_resources：新表
id int8 PRIMARY KEY DEFAULT nextval('ai_skill_resources_seq')   -- NexAI 每表 id 主键惯例
version_id int8 NOT NULL                            -- → ai_skill_version.id
resource_path varchar(500) NOT NULL
resource_content text NOT NULL
+ TenantBaseDO 通用列（creator/create_time/updater/update_time/deleted/tenant_id）
-- 唯一索引：uk_ai_skill_resources (version_id, resource_path) WHERE deleted=0
-- 新序列 ai_skill_resources_seq；无数据库级 FK（项目惯例逻辑关联）
```

资源行**只插不改**——版本不可变的物理体现（追加版本=新 version_id 全量插入新资源行）。

### 3.2 领域模型

- `Skill` 聚合根：+`published`（boolean，行为 `publish()` / `unpublish()`）+ `gitSourceId`（Long，只读标记——工单 29 同步用例创建时设置，无领域修改行为）。
- `SkillContent` 值对象：原样保留，不加新不变量（单资源大小无上限、数量 ≤128、markdown ≤65536 字符——维持现状）。
- `SkillOwnerLevel`：删除 `PLATFORM` 枚举值。`parseOwnerLevel` 现有拒绝逻辑随之简化。
- 不新增实体/值对象——资源是 `SkillContent` 内的 Map，持久化时展开成行。

### 3.3 基础设施

- `SkillDO`：+`published`（Integer 0/1）、+`gitSourceId`；`SkillVersionDO`：`content` → `skillMarkdown`（列 `skill_markdown`）。
- 新增 `SkillResourceDO`（id/versionId/resourcePath/resourceContent，TenantBaseDO）与 `SkillResourceMapper`（批量插入、`selectListByVersionId` 查未删除行）。
- `SkillConverter`：删除 `ContentJSON` 桥接与 `contentToJson` / `jsonToContent`；新增资源 Map ↔ 资源 DO 行的 default 转换方法；新增 `published` 的 boolean ↔ Integer(0/1) 映射。转换仍集中一处。
- `SkillRepositoryImpl`：
  - `saveVersion`：事务内「版本行 + 资源行批量插入」（≤128 行/版本，`saveBatch` 足够）；
  - **读取路径分层**：`version-page` 的轻量列表本就经 Mapper 直查转 DTO（不经 Repository）；`Repository.listVersions` 保持全量装配（含资源，唯一消费方 `AgentRuntimeAssembler` 零改动——`SkillVersion` 的 content 非空约束使「半内容」对象不可构造）；新增端口 `findVersion(skillId, versionNo)` 提供精确单版本读取（含 markdown 与资源），供工单 27 预览与后续精确取用；
- 物化网关、`AgentRuntimeAssembler` 挂载解析：零改动（消费领域模型）。

### 3.4 接口与前端

- 新增 `POST /ai/skill/publish?id=` 与 `POST /ai/skill/unpublish?id=`（复用 `ai:skill:update` 权限，不新增权限点）。
- `SkillDTO`：+`published`（Integer 0/1）、+`gitSourceId`。
- 管理页列表：「上架」开关列（el-switch，`active-value=1` / `inactive-value=0`）与「来源」标记（gitSourceId 非空显示 Git）。
- 既有 5 接口行为不变（回归）。

### 3.5 测试与脚本

- 纯 JUnit：`Skill.publish()/unpublish()` 行为；既有 `SkillContent` 测试保留不动。
- H2 单测（BaseDbUnitTest）：repository 双表读写（saveVersion → findVersion 断言 markdown + 资源全量往返）；资源无 update 路径（结构性约束，代码评审保证）；controller 的 publish/unpublish 与既有 5 接口回归。
- PG 集成：物化契约（资源从表读出物化目录结构正确，含 base64 二进制资源落盘）；挂载解析回归。
- `ruoyi-vue-pro.sql`：AI 段三表 DROP 重建 + 新序列 + 中文 COLUMN/TABLE COMMENT。

## 4. 决策记录

| 决策 | 结论 |
| --- | --- |
| 上架位形态 | int 两态（0/1），不用枚举状态机（审核流 YAGNI） |
| 版本演进对上架位的影响 | 追加/切换版本保持上架（27 落地） |
| git 同步重建对上架位的影响 | 同步用例继承旧同名 skill 的上架位（工单 29 的契约，本票只保证字段存在） |
| published 分层类型 | DDL/DO/DTO 层 Integer(0/1)；领域模型 boolean；converter 映射 |
| 资源建模 | 聚合内 Map（值对象），不升格实体；行只插不改 |
| git_source_id | 26 先加裸列，无 FK；表归 29 |
| 存量数据 | DROP 重建清空（既有约定） |

## 5. 已知边界与风险

- `published` NOT NULL DEFAULT 0，不受「MyBatis Plus updateById 跳过 null」坑影响；`gitSourceId` 可空，仅插入时设置、无置空场景。
- `skill_markdown` text 列 PG 无长度上限，应用层 65536 字符上限由值对象保证。
- H2 与 PG 的 DDL 兼容：全部使用标准类型（int8/int4/varchar/text），无 PG 专属语法（无 jsonb/无数组）。
