## 二、演示脚本（管理界面操作序）

1. **配渠道**（模型管理 → 渠道页签）：新建渠道（提供商 openai-compat、端点、密钥）；保存前点「测试连通」验证凭据。验证点：密钥密文落库（列表只见脱敏 `sk-a***b`）；停用渠道后模型不可用。
2. **建模型**（模型页签）：在渠道下登记模型（标识、上下文窗口、单价、能力标签）；模型级「测试连通」走已存密钥。
3. **写规格**（智能体规格）：新建规格，引用上述模型，填系统提示与推理参数（maxIters/温度），保存为草稿。
4. **发布版本**：发布草稿 → 版本历史出现不可变 v1 快照；改草稿再发布得 v2；可切换默认版本。
5. **调试台多轮对话**：新建调试会话（选规格与版本）→ 发两轮消息（第一轮自我介绍、第二轮追问）→ 验证回复体现跨轮记忆（状态存储恢复）；中栏实时渲染事件流（思考/文本/工具卡片/token 用量）。
6. **中断**：对一条长回复点「停止」→ 流以正常序列收尾，不留悬挂状态。
7. **HITL 三态**：M1 生产链路无触发确认的工具，本项由 S1 自动化测试覆盖（`DebugSessionControllerTest` 的挂起/批准/改参批准/拒绝四路径）；界面演示留待 M2 权限引擎接入（US25 同一通道）。
8. **克隆重跑**：会话列表 hover → 克隆，微调温度/maxIters → 新会话携带完整历史可继续追问。
9. **提交带截图反馈**（问题反馈）：关联会话编号，截图经 `/infra/file/upload` 直传后只存 URL。
10. **管理员处理闭环**：反馈列表过滤 → 流转 待处理 → 处理中 → 已解决/已关闭。

## 四、2026-08-22 验收结论

- S1/S3 回归：`mvn test -pl nexai-module-ai` 147 例全绿（19 个测试套件，0 失败 0 错误；surefire 报告在 `nexai-module-ai/target/surefire-reports/`，可复核）。
- S5 冒烟（mock 模式）：全流程 9 步通过（见下方记录），修复后复跑仍全绿。
- 真实凭据场景：spike（工单 01）已验证真实 DeepSeek 全事件流与跨请求记忆恢复；本轮无可用云凭据，真实模式以「脚本可重跑 + 操作口径」交付，持凭据者执行第三节 real 命令即可复核（real 模式的记忆恢复断言用第 2 轮输入 token ≥ 60 的模型无关指标，不依赖模型按稿复述）。
- 界面演示：调试台三栏工作台、多轮对话、中断、克隆（参数覆盖 + 历史复制）、模型管理（密钥脱敏）、规格（无草稿禁发布）、反馈流转经管理界面人工走查通过。
- 环境对齐操作（重建环境需知）：工单 08 的菜单 6425/6426（`ai:session:interrupt/clone`）此前仅落全量脚本未在开发库执行，本轮已在开发库补插并将 `system_menu_seq` 前移至 6427；全量初始化的环境无此问题。
