# 领域文档

工程 skill 在探索本仓库代码前，应如何消费领域文档。

## 探索前先读

- 仓库根目录的 **`CONTEXT.md`**；
- 若存在根目录 **`CONTEXT-MAP.md`**，按其指向读取与当前主题相关的各 `CONTEXT.md`；
- **`docs/adr/`** —— 阅读与即将工作的区域相关的 ADR。

以上文件若不存在，**静默继续**。不要标记其缺失，也不要预先建议创建——`/domain-modeling` skill（经 `/grill-with-docs` 与 `/improve-codebase-architecture` 触达）会在术语或决策真正落定时惰性创建它们。

## 文件结构（单上下文本仓库）

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── （源代码树）
```

## 使用术语表的词汇

当你的产出提及领域概念（工单标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 中定义的术语，不要漂移到术语表明确回避的同义词。

若所需概念尚不在术语表中，这是一个信号——要么你在发明项目不用的语言（请重新考虑），要么存在真实空缺（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的产出与既有 ADR 矛盾，显式指出而不是静默覆盖：

> _与 ADR-0007（xxx）矛盾——但值得重开，因为……_
