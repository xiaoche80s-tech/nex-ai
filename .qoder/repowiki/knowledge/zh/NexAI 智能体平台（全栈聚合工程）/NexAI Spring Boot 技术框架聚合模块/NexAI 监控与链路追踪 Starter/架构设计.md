模块以 `com.gkht.ai.nexai.framework.tracer` 为根包，按职责划分为 config / core/annotation / core/aop / core/filter / core/util 子包：
- 自动装配入口：通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册 `NexaiTracerAutoConfiguration` 与 `NexaiMetricsAutoConfiguration`，由 Spring Boot 在启动时按需加载。
- Tracer 配置层：`NexaiTracerAutoConfiguration` 使用 `@ConditionalOnClass`（依赖 `io.opentelemetry.api.trace.Tracer` 与 `jakarta.servlet.Filter`）和 `@ConditionalOnProperty(prefix="nexai.tracer", value="enable", matchIfMissing=true)` 控制开关；暴露 `Tracer` Bean（基于 `GlobalOpenTelemetry`）、`BizTraceAspect` AOP 切面及 `FilterRegistrationBean<TraceFilter>`，并通过 `WebFilterOrderEnum.TRACE_FILTER` 设定过滤顺序。
- 业务埋点层：`@BizTrace` 注解标记方法，`BizTraceAspect` 通过 AspectJ `@Around` 拦截，创建 `Span` 并设置 `component=biz`，支持通过 SpEL 表达式解析 `type()`/`id()` 注入 `biz.type`/`biz.id` 标签，异常经由 `TracerFrameworkUtils.onError` 上报后重新抛出。
- HTTP 透传层：`TraceFilter` 继承 `OncePerRequestFilter`，在响应头写入 `trace-id`，依赖 `TracerUtils.getTraceId()` 获取当前链路 ID。
- 指标层：`NexaiMetricsAutoConfiguration` 在存在 `MeterRegistryCustomizer` 时启用，统一为所有指标添加 `application` 公共标签。
- 依赖方向：本 starter 仅依赖 `nexai-common`、Spring Web/Servlet API（provided）以及可选的 OpenTelemetry、SkyWalking、Micrometer Prometheus、Spring Boot Admin Client（均为 optional），保证引入方按需组合能力。
