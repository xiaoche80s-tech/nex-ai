模块以 Spring Boot Starter 形式暴露，通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 注册两个自动配置类：`NexaiDataPermissionAutoConfiguration` 负责装配核心 Bean（`DataPermissionRuleFactory`、`DataPermissionRuleHandler`、`DataPermissionAnnotationAdvisor`），将自定义的 `MultiDataPermissionHandler` 插入到 MyBatis-Plus 拦截器链首位；`NexaiDeptDataPermissionAutoConfiguration` 提供部门维度规则实现。

内部按职责分层：
- `core/annotation`：定义 `@DataPermission` 注解，支持 `enable`、`includeRules`、`excludeRules` 控制规则生效范围。
- `core/aop`：`DataPermissionAnnotationInterceptor` 作为 AOP 拦截器在执行方法前后将注解入栈/出栈到 `DataPermissionContextHolder`，并缓存注解解析结果避免重复反射。
- `core/db`：`DataPermissionRuleHandler` 实现 MP 的 `MultiDataPermissionHandler`，在 SQL 执行前根据 `mappedStatementId` 获取匹配规则列表，逐个表名比对后拼接 `AndExpression` 条件；通过 `SecurityFrameworkUtils.skipPermissionCheck()` 支持跨租户等跳过场景。
- `core/rule`：抽象出 `DataPermissionRule` 接口（声明 `getTableNames` + `getExpression`），由 `DataPermissionRuleFactoryImpl` 根据注解与上下文筛选规则集合；`dept/` 子包提供默认实现 `DeptDataPermissionRule`，从 `LoginUser` 上下文读取部门权限并通过 JSqlParser 构建 `IN` / `EqualsTo` / `OrExpression` 等表达式。
- `core/util`：`DataPermissionUtils` 提供工具方法。

依赖方向单向向外：AOP → DB Handler → Rule Factory → Rule 实现；业务方只需实现 `DataPermissionRule` 并配合 `@DataPermission` 即可扩展新规则。
