- 跨模块领域能力以「接口 + DTO」形式暴露于 `biz/system/*` 或 `biz/infra/*` 下，接口只定义方法签名，DTO 放在同目录 `dto/` 子包中，实现由具体业务模块提供。
- 对外统一返回体采用泛型 `CommonResult<T>`，并通过 `success()/error(ErrorCode)/checkError()` 等静态工厂与便捷方法构造，错误码集中维护在 `GlobalErrorCodeConstants`。
- 业务异常统一继承 `ServiceException`，携带 `code` 与 `message`，并通过 `ServiceExceptionUtil.doFormat` 进行参数化消息格式化。
- 自定义参数校验通过 Jakarta `@Constraint` 注解 + 对应 Validator 类成对实现（如 `InEnum` + `InEnumValidator` / `InEnumCollectionValidator`），枚举值域校验要求枚举实现 `ArrayValuable` 接口。
- 工具类均为纯静态方法集合，按功能域拆分子包（collection/date/http/io/json/servlet/string/spring/number/object/cache/monitor），避免持有状态；需要外部配置时提供 `init(...)` 静态入口（如 `JsonUtils.init(ObjectMapper)`）。
- 第三方依赖在 `pom.xml` 中普遍声明为 `provided` 作用域，仅在确需编译期类型时才引入，确保该模块作为轻量基础库被上层应用自行管理依赖版本。
