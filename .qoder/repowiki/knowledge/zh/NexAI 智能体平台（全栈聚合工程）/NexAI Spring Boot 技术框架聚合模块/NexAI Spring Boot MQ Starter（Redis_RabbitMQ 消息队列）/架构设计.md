模块以 Spring Boot AutoConfiguration 为核心入口，通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 声明三个自动配置类：`NexaiRedisMQProducerAutoConfiguration`、`NexaiRedisMQConsumerAutoConfiguration`、`NexaiRabbitMQAutoConfiguration`，由 Spring Boot 在运行时按需加载。

- 分层结构：按消息中间件划分为 `rabbitmq/` 与 `redis/` 两个子包；`redis/` 内部再按职责拆分为 `config`（自动装配）、`core`（模板与抽象基类）、`core/interceptor`（消息拦截器）、`core/message`（消息基类）、`core/pubsub`（广播订阅）、`core/stream`（集群消费）、`core/job`（定时任务）。
- 生产者侧：`RedisMQTemplate` 作为统一发送门面，对 `AbstractRedisChannelMessage`（基于 `convertAndSend`）与 `AbstractRedisStreamMessage`（基于 `opsForStream().add`）分别重载 `send`；发送前后通过 `RedisMessageInterceptor` 链执行 before/after 钩子（正序 before、倒序 after）。
- 消费者侧：`NexaiRedisMQConsumerAutoConfiguration` 根据是否存在自定义的 `AbstractRedisChannelMessageListener` / `AbstractRedisStreamMessageListener` 子类，使用 `@ConditionalOnBean` 条件注册 `RedisMessageListenerContainer`（Pub/Sub）或 `StreamMessageListenerContainer`（Stream），并为 Stream 模式创建消费者分组、设置 `autoAcknowledge=false` 并手动 ack。
- 可靠性保障：`RedisPendingMessageResendJob` 与 `RedisStreamMessageCleanupJob` 通过 `@Scheduled` + Redisson 分布式锁定期扫描 pending 队列，对超时未 ack 的消息重新投递并清理已消费记录。
- 依赖方向：配置类依赖 `nexai-framework-common` 中的 `JsonUtils`、`DocumentEnum` 等工具，以及 `nexai-framework-redis` 提供的 `NexaiRedisAutoConfiguration` 与 `RedissonClient`；RabbitMQ 配置通过 `@ConditionalOnClass(RabbitTemplate)` 实现可选依赖，避免引入 amqp 时启动失败。
- 扩展点：用户只需继承 `AbstractRedisChannelMessage` / `AbstractRedisStreamMessage` 定义消息体，继承对应 Listener 实现 `onMessage`，并通过实现 `RedisMessageInterceptor` 注入横切逻辑。
