模块按三层划分：
- API 层（`api/sms/`）：定义 `SmsCodeApi`、`SmsSendApi` 两个对外 RPC 接口及对应 `*Impl` 实现（如 `SmsCodeApiImpl`），仅做参数校验后委托给 Service 层，供其他模块远程调用。
- Controller 层（`controller/admin/sms/`）：基于 Spring MVC 暴露管理后台 REST 接口，包含 `SmsTemplateController`、`SmsChannelController`、`SmsLogController`、`SmsCallbackController`；其中 `SmsCallbackController` 通过 `@PermitAll` + `@TenantIgnore` 接收阿里云、腾讯云、华为云、七牛云的短信状态回调。
- Service 层（`service/sms/`）：以 `SmsCodeService`、`SmsSendService`、`SmsTemplateService`、`SmsChannelService`、`SmsLogService` 五个接口及其 `ServiceImpl` 实现业务编排，依赖 DAL 的 `*Mapper` 和框架层的 `SmsClient` 抽象来对接不同短信厂商。
依赖方向严格自上而下：Controller → Service → Mapper/Redis/MQ；API Impl 直接依赖 Service 而非 Controller，保证跨模块复用。模板创建/更新时通过 `SmsChannelService.getSmsClient()` 调用远端平台校验模板审核状态，并将模板内容中的 `{param}` 变量解析为 JSON 持久化。
