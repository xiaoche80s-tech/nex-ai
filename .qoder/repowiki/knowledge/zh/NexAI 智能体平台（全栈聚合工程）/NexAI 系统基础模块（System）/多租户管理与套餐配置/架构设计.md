模块采用典型的 Controller-Service-API 三层结构：
- API 层 `api/tenant/TenantApiImpl` 实现框架提供的 `TenantCommonApi`，对外暴露 `getTenantIdList` 与 `validateTenant`，供其他模块在运行时获取租户列表或校验租户合法性。
- Controller 层位于 `controller/admin/tenant`，`TenantController` 负责 `/system/tenant` 下的租户管理（创建、更新、删除、分页、导出 Excel），`TenantPackageController` 负责 `/system/tenant-package` 下的套餐管理；部分登录相关接口标注 `@PermitAll` + `@TenantIgnore` 以绕过租户上下文。
- Service 层位于 `service/tenant`，`TenantServiceImpl` 通过 `TenantMapper` 操作数据，并依赖 `TenantPackageService`、`RoleService`、`MenuService`、`PermissionService`、`AdminUserService` 完成创建租户时自动建角色、分配菜单权限等编排逻辑；所有写操作使用 `@DSTransactional` 保证多数据源事务。
- 扩展点通过 `handler` 子包中的 `TenantInfoHandler`、`TenantMenuHandler` 两个函数式接口暴露，由调用方传入 Lambda 处理租户信息或菜单集合，从而将租户相关副作用从核心服务中解耦。
- 依赖方向单向：API → Service → Mapper/其他业务 Service，Controller 仅做参数校验与 VO 转换，不持有持久化逻辑。
