模块采用典型的 Controller-Service-DAL 三层结构：
- 控制层：`ConfigController`（/infra/config）和 `DataSourceConfigController`（/infra/data-source-config）分别暴露 REST 接口，统一通过 `CommonResult` 包装返回，使用 `@PreAuthorize("@ss.hasPermission(...)" )` 进行细粒度权限控制，并通过 `@Validated` + VO 完成入参校验。
- 服务层：`ConfigService` 接口及其 `ConfigServiceImpl` 实现封装业务规则（如 key 唯一性校验、内置 SYSTEM 类型不可删除），通过 `ConfigMapper` 访问数据库；`DataSourceConfigController` 直接委托给 `DataSourceConfigService`（位于 infra 模块其他包）。
- 数据转换：使用 MapStruct 风格的 `ConfigConvert.INSTANCE` 在 VO 与 DO 之间转换；数据源配置则复用框架的 `BeanUtils.toBean`。
- 安全与审计：导出接口通过 `@ApiAccessLog(operateType = EXPORT)` 记录操作日志；敏感字段（`visible=false` 的配置值）在 `getConfigKey` 中显式拒绝返回。
依赖方向单向向下：Controller → Service → Mapper → DB，VO 仅存在于 controller 包内作为请求/响应契约。
