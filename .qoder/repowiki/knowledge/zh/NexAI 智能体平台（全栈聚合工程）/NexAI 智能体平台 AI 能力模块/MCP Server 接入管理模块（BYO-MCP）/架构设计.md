采用清晰的分层 DDD 结构：
- interfaces 层：Spring MVC Controller（`McpServerController`）暴露 `/admin-api/ai/mcp-server/*` REST 接口，统一通过 `CommonResult` 包装并基于 `@PreAuthorize` 做权限控制。
- application 层：以 Command/Query/DTO 作为输入输出契约，`McpServerService` 编排创建、更新、状态切换、删除、分页与连通探测等用例；命令对象集中定义在 `application/command`，DTO 在 `application/dto`，查询对象在 `application/query`。
- domain 层：聚合根 `McpServer`（充血模型，零框架依赖）封装传输类型、端点/命令、认证头、超时、工具白名单与可用工具清单等不变量校验；值对象 `McpConnectionConfig`/`McpTransport`/`McpOwnerType`/`McpProbeResult`/`McpToolSummary` 表达领域概念；通过 `domain/gateway/McpServerGateway` 与 `domain/repository/McpServerRepository` 两个端口隔离外部依赖。
- infrastructure 层：`McpServerRepositoryImpl` 借助 MyBatis Mapper + `McpServerConverter` 完成 DO↔聚合转换，枚举编码非法时直接抛异常暴露脏数据；`AgentscopeMcpServerGateway` 基于 agentscope `McpClientWrapper` 实现 initialize+listTools 探测，失败原因封装进 `McpProbeResult` 而非抛异常；`McpClientFactory` 复用运行时装配的建连路径。
依赖方向严格自外向内：interfaces → application → domain ← infrastructure，domain 不感知任何 Spring/MyBatis/agentscope 细节。
