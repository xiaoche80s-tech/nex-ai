采用分层 + DDD 风格组织：
- `interfaces/controller/admin/channel`：Spring MVC 控制器，通过 `@PreAuthorize` 权限注解暴露 `/ai/channel` 下的 REST API。
- `application`：以 Command/Query/DTO 作为应用层契约，`ChannelService`/`ModelService` 编排业务用例（创建、更新、启停、删除、分页、连通性探测），写操作走领域聚合，读操作经 `ChannelMapper` 直查实现读写分离。
- `domain`：纯 Java 聚合根 `Channel`（含 `enable/disable` 等状态行为、`maskedApiKey` 脱敏）与实体 `Model`；值对象 `ChannelProvider`、`ChannelOwnerType`、`ConnectivityResult`、`ApiKeyMasker`；通过 `ChannelRepository` 端口与 `ModelConnectivityGateway` 端口隔离外部依赖。
- `infrastructure`：`ChannelRepositoryImpl` 将 DO ↔ 领域模型转换并处理级联删除；`ChannelMapper`/`ModelMapper` 基于 MyBatis Lambda 查询；`ChatModelFactory` 按 `ChannelProvider` 构造 agentscope 各厂商 `ChatModel`，并通过 `AgentscopeModelConnectivityGateway` 实现连通性探测。
依赖方向严格自上而下：interfaces → application → domain ← infrastructure，领域层不依赖 Spring。
