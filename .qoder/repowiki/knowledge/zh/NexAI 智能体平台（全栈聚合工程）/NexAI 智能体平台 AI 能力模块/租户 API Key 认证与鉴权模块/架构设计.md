采用分层 + DDD 风格组织：
- `interfaces/controller/admin/apikey/ApiKeyController` 暴露管理后台 REST（`/admin-api/ai/api-key`），通过 `@PreAuthorize` 控制 `ai:api-key:*` 权限。
- `application/service` 定义 `ApiKeyService` 端口，封装创建、分页、吊销用例；入参使用 `command/*`（如 `ApiKeyCreateCommand`）和 `query/*`（如 `ApiKeyPageQuery`），出参使用 `dto/*`（`TenantApiKeyDTO`、`ApiKeyCreatedDTO`）。
- `domain/model` 中 `TenantApiKey` 作为聚合根，维护 `ENABLED/REVOKED` 状态机、规格白名单校验（`allowsSpec`）、名称/前缀长度等不变式；`domain/repository/TenantApiKeyRepository` 仅声明接口。
- `infrastructure` 实现持久化与网关：`dataobject/TenantApiKeyDO` + `mapper/TenantApiKeyMapper` + `repository/TenantApiKeyRepositoryImpl` 完成 DO↔Domain 映射，`converter/ApiKeyConverter` 负责 DTO↔Domain 转换；`gateway/ApiKeyAuthFilter` 继承 `OncePerRequestFilter`，拦截 `/app-api/ai/openai/**`，从 `Authorization: Bearer <key>` 或 `X-API-Key` 提取明文后以 `Hashes.sha256Hex` 查库，成功则恢复 `TenantContextHolder` 并注入请求属性 `nexaiAuthenticatedApiKey`，失败返回 OpenAI 兼容 JSON 401。
依赖方向严格自上而下：controller → application service → domain repository → infrastructure mapper，领域层不依赖基础设施。
